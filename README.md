## Лабораторная №3: Настройки, пользователи и логирование

### 1. Разделение настроек
Настройки разделены на пакет `config/settings/`:
* `base.py` — общие настройки.
* `dev.py` — для разработки (DEBUG=True).
* `prod.py` — для продакшена (DEBUG=False, настройки безопасности).
Секреты (`SECRET_KEY`, `DATABASE_URL`, `ALLOWED_HOSTS`) вынесены в `.env`. В репозитории есть шаблон `.env.example`.

### 2. Почему переход на кастомного пользователя потребовал пересоздания базы
При попытке применить миграции для новой модели `User` (наследника `AbstractUser`) возникла ошибка `InconsistentMigrationHistory`. Это произошло потому, что встроенная миграция `admin.0001_initial` уже была применена ранее и ссылалась на старую таблицу `auth_user`. Django не может задним числом изменить зависимости уже примененных миграций. Поэтому кастомную модель пользователя нужно создавать в самом начале проекта, до первого запуска `migrate`. В рамках учебной лабораторной база была удалена (через `docker compose down -v`) и пересоздана заново, данные сотрудников восстановлены.

### 3. Логирование и N+1 запросы
Настроен `LOGGING` в `base.py` (вывод в консоль). Создание и удаление сотрудников через API логируется в `employees/views.py`.

**Проблема N+1 запросов:**
При выводе списка сотрудников с названиями их отделов (поле `department_name`) изначально выполнялось 1 запрос на получение списка сотрудников и N запросов на получение названия отдела для каждого сотрудника. 
* **До исправления:** 11-12 запросов (в зависимости от количества сотрудников).
* **После исправления:** В `EmployeeViewSet` был добавлен метод `select_related("department")`. Благодаря этому Django использует SQL JOIN и достает все данные за 1 запрос (плюс 2-3 служебных запроса на сессию и авторизацию).
